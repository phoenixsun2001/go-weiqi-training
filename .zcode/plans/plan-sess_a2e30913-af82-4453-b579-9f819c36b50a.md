# 训练素材完善计划

## 现状（已核实）
- **定式**：14 个齐全，计划引用的都有，但缺 2 个专题（拆边距离、打入侵消），概念无索引
- **死活题**：420 道（easy 140 / intermediate 140 / hard 140），无基础死活形（直三/板六等），`insert_problem` 无去重
- **复盘匹配**：95 局对局库，AI 复盘（`review_game`）实时重算不落库；issues 覆盖"过早接触战/序盘急于战斗/中腹浮棋风险"，**缺"孤棋被攻击"检测**；`game_state.py` 有连通块+气计算可复用

## 一、定式素材（joseki_data.py + 后端接口）
1. 新增 2 个专题定式（带棋理解读）：
   - "拆边专题·一间拆/二间拆/大飞"（布局类，难度1）→ 对应计划第2周d5"学习拆边距离"
   - "打入与侵消·基本型"（中盘类，难度3）→ 对应计划第3周d2"学习打入与侵消"
2. 概念索引接口 `GET /api/joseki/concepts`：从全部定式的 principles 聚合 concept → 相关定式列表（"攻击的时机"、"弃子取势"、"拆边的距离"等任务可直接定位）

## 二、死活题素材（补充 15 道基础死活形）
1. 新增经典角部死活形 SGF（答案可靠、对应 JadenSai"角部占领不足"弱点）：
   - easy 7 道：直三杀/直三活、曲三、丁四、刀把五、梅花五、板六
   - intermediate 8 道：盘角曲四、金柜角、小猪嘴、大猪嘴、老鼠偷油等
2. 生成脚本写入 `backend/resources/tsumego/easy|intermediate/`
3. `seed_problems` 加按 question_sgf 去重（防重复导入），重跑导入

## 三、典型复盘对局匹配（核心，后端）
1. **ai_review.py 增强**：中盘新增"孤棋被攻击"检测——重建盘面（复用 `game_state._group_and_liberties` 连通块/气），检测 reviewee 中腹孤立棋块（无眼位、气少、与己方无联络）→ 新 issue "孤棋被攻击"
2. **新建 `backend/game_matcher.py`**：遍历对局跑 `review_game`（进程内缓存避免重复计算），按任务条件匹配：
   - 负局 loss / 胜局 win（用 reviewee_won）
   - 过早接触战（布局期"过早接触战"issue，第1周d6）
   - 序盘急于战斗（"序盘急于战斗"，第2周d3）
   - 中腹浮棋（"中腹浮棋风险"/"序盘中腹浮棋"，第2周d6、第3周d3）
   - 孤棋被攻击（新 issue，第3周d6）
   - 返回每类 top N 对局：game_id、日期、对手、胜负、匹配理由
3. **main.py**：`GET /api/training/matches` 一次返回所有复盘任务的匹配对局

## 四、前端
1. `api.ts`：`getTrainingMatches()`、`getJosekiConcepts()`
2. `TrainingView.tsx` 增强：
   - 复盘类任务卡片显示匹配对局列表（日期/对手/胜负/理由），点击直接进入该局 AI 复盘（onReviewGame）
   - 定式类任务显示"相关定式"卡片（概念索引+名称模糊匹配），点击跳转定式模块自动选中
   - 题库任务跳转时带难度
3. `JosekiView.tsx`：支持 `initialName` prop 自动选中定式
4. `App.tsx`：TrainingView 接入 onReviewGame；跳转定式带目标名

## 五、验证与部署
1. 本地：素材脚本生成 → 题库导入验证（415 道无重复）→ 匹配接口测试（各任务类目都返回对局）→ 前端构建
2. 服务器：git pull + npm build + 重启 + 题库重导入 + 匹配接口公网验证
