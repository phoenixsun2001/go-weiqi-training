# Web 架构迁移计划：Tauri 桌面应用 → Python FastAPI + React Web

## 目标
将应用从 Tauri exe 改为 **Python FastAPI 后端 + React 前端**，保留全部现有功能，同时修复剩余 30% 的缺陷（棋力面板可视化、段位校准、题库扩充、复盘流式进度）。

## 架构概览
```
用户浏览器 (React SPA)
    ↕ HTTP REST + WebSocket
Python FastAPI 后端 (localhost:8000)
    ├── KataGo GTP 子进程管理（对战引擎 + 分析引擎）
    ├── SQLite 数据库（档案/对局/题库/复盘/弱点）
    └── 题库资源（420 道 SGF）
```

## 实现步骤

### 第一阶段：后端核心移植（Python）

**Step 1: 基础模块移植**
将 Rust 核心逻辑逐模块移植到 Python：
- `coords.py`：gtp_to_xy / xy_to_gtp（跳过 I）
- `game_state.py`：落子/提子/劫/自杀/pass（10 个测试用例移植）
- `sgf_parser.py`：parse_moves / export_sgf / parse_metadata / extract_tsumego_answer
- `rating.py`：expected_score / update_elo / dan_from_elo

**Step 2: 数据库层**
- `store.py`：用 aiosqlite 或 sqlite3，复用现有 schema（001_init.sql）
- 自动建表 + 默认档案 + 题库 seed

**Step 3: KataGo 引擎管理（最关键）**
- `katago_engine.py`：asyncio 管理子进程，stdin/stdout 通信
- 修复 os error 232 根因：stderr 重定向到日志文件而非管道
- 两个引擎实例：opponent（对战）+ analysis（复盘）
- 配置生成器：低内存优化配置（maxVisits=300, threads=3）

**Step 4: API 路由（36 个端点）**
将 36 个 Tauri 命令映射为 REST 端点：
- `POST /api/game/new` `POST /api/game/play` `GET /api/game/snapshot`
- `POST /api/engine/start` `POST /api/engine/ai-move`
- `POST /api/review/analyze`（**WebSocket** 流式推送每手胜率）
- `GET /api/problems/next` `POST /api/problems/submit`
- `POST /api/library/import` `GET /api/library/list`
- 等等

### 第二阶段：前端适配

**Step 5: IPC 层替换**
- 新建 `src/lib/api.ts`：用 `fetch` 替换 `invoke`
- 统一 API 命名（全部 snake_case，去掉 args wrapper）
- 更新 `gameStore.ts` 中的 import

**Step 6: 复盘 WebSocket 流式进度**
- ReviewView 改为 WebSocket 连接 `/ws/review`
- 逐手接收 KataGo 分析结果，实时更新胜率曲线

### 第三阶段：剩余 30% 功能补全

**Step 7: 棋力面板可视化**
- 新增 `RatingPanelView`：Elo 历史曲线 + 段位 + 训练建议
- 后端 `GET /api/rating/history` 返回评级历史

**Step 8: 段位校准工具**
- 后端 `POST /api/admin/calibrate`：用已知棋谱测试 KataGo 不同 visits 的实际棋力
- 生成 dan→visits 校准表

**Step 9: 题库扩充**
- 导入更多开源题库（Cho Chikun 等经典死活）
- 按段位精细分级（1d-5d 各 50+ 题）

**Step 10: 一键启动 + 文档**
- `start.bat`：启动 Python 后端 + 自动打开浏览器
- 更新 README
